# خط الأساس لاكتمال لسان

هذا المستند يعرّف معنى "اكتمال" لسان بشكل موحّد عبر اللغة والمكتبات والأدوات، ويحدد معيار قبول ثابت لأي ميزة جديدة.

## تعريف الاكتمال

تُعد الميزة مكتملة فقط إذا تحققت العناصر التالية كلها:

1. **سلوك صحيح**: تعمل الميزة كما هو موثق في التنفيذ الفعلي.
2. **اختبارات**: توجد اختبارات تغطي الحالة الأساسية والحالات الحدّية والفشل المتوقع.
3. **توثيق**: توثيق الاستخدام والقيود وأمثلة تشغيل واضحة.
4. **CI أخضر**: تمر الميزة ضمن مسار GitHub Actions المعتمد.
5. **اتساق المسارات**: لا يظهر تعارض سلوكي غير مبرر بين المفسّر وVM والمسار الأصلي.

## معيار القبول الموحد (Definition of Done)

أي تغيير يُعتبر "منتهيًا" فقط بعد:

- [ ] إضافة/تحديث اختبارات Rust المناسبة.
- [ ] تحديث أمثلة `examples/` عند الحاجة.
- [ ] تحديث وثائق `README.md` أو `docs/*.md` بما يطابق السلوك.
- [ ] التأكد من نجاح أمر الاختبارات الأساسي:
  - `cargo test --all-targets`
- [ ] التأكد من نجاح مسارات CLI الأساسية عند الحاجة:
  - `cargo run -- --interpret examples/hello.lsn`
  - `cargo run -- --check examples/modules/main.lsn`

## معايير قبول حسب المجال

### 1) نواة اللغة

- [ ] قواعد Lexer/Parser محددة بوضوح ولا تكسر الصيغ الحالية.
- [ ] سلوك التنفيذ موحد عبر المفسّر وVM.
- [ ] أي اختلاف معروف موثق صراحة في مستند مناسب.

### 2) المكتبة القياسية

- [ ] توقيع الدالة وسلوك الأخطاء موثقان.
- [ ] توجد اختبارات نجاح وفشل لكل دالة جديدة أو معدلّة.
- [ ] أمثلة واقعية محدثة عند إضافة واجهات جديدة.

### 3) الأدوات (CLI/Diagnostics/Editor)

- [ ] رسائل أخطاء عربية واضحة وقابلة للتنفيذ.
- [ ] خيارات CLI موثقة ومتسقة مع `--help`.
- [ ] أي تكامل محرّر (VS Code) مرفق بتحديثات التوثيق.

### 4) الإنتاجية والنظام البيئي

- [ ] أي مكوّن مدير حزم/نشر يُعرّف تنسيقًا ثابتًا وتحققًا واضحًا للأخطاء.
- [ ] توثيق الترقية والتوافق بين الإصدارات متاح قبل الاعتماد العام.

## ملاحظات تنفيذية

- لا تُقاس الجاهزية برقم الإصدار فقط، بل باستيفاء معايير القبول.
- تنفيذ خارطة الطريق يتم على مراحل صغيرة، كل مرحلة قابلة للدمج والاختبار بشكل مستقل.
