# مسارات تنفيذ لسان والفروقات المعروفة

هذا المستند يوضح الفروقات الحالية بين مسارات تنفيذ لسان، حتى تكون الحدود معروفة بشكل صريح أثناء التطوير.

## المسارات المتاحة

- `--interpret`: تنفيذ مباشر عبر المفسّر.
- `--vm`: تنفيذ عبر آلة بايت كود افتراضية.
- `--native`: ترجمة إلى ملف آلة أصلي عبر LLVM IR + Clang.
- `--build`: حزمة تنفيذية مستقلة تضم المفسّر والبرنامج بعد حل الاستيرادات.

## مصفوفة دعم مختصرة

| المجال | interpret | vm | native | build |
|---|---|---|---|---|
| تغطية ميزات اللغة العامة | أعلى تغطية | تغطية جيدة لمسار VM | تغطية جزئية (بحسب الميزة) | نفس المفسّر تقريبًا |
| ميزات ديناميكية متقدمة | مدعومة | قد تختلف حسب تنفيذ VM | غير مدعومة بالكامل | مدعومة عبر المفسّر |
| الاعتماد على Clang | لا | لا | نعم (وقت البناء) | لا |
| ناتج ملف آلة أصلي خالص | لا | لا | نعم | لا |
| مناسب للتجارب السريعة | نعم | نعم | أقل (يتطلب ترجمة) | متوسط |

## فروقات معروفة يجب أخذها بالحسبان

1. **المسار الأصلي (`--native`) ليس مكافئًا كاملًا للمفسّر بعد**  
   توجد ميزات ديناميكية ما زالت مرفوضة أو غير مكتملة في المسار الأصلي مقارنةً بالمفسّر.

2. **مسار `--build` هو تغليف للمفسّر وليس ترجمة آلة مباشرة**  
   الملف الناتج مستقل للتشغيل، لكنه يحمل runtime المفسّر، وليس ناتج LLVM مباشرًا.

3. **مسار VM قد يختلف سلوكيًا في بعض الزوايا عن المفسّر**  
   الهدف هو تقليل الفروقات تدريجيًا، ويجب تثبيت أي فرق معروف بالاختبارات والتوثيق.

## سياسة الإغلاق التدريجي للفروقات

- عند اكتشاف فرق سلوكي:
  1) يوثق الفرق هنا باختصار واضح.
  2) يضاف اختبار يثبت السلوك الحالي.
  3) عند الإصلاح، يزال الفرق من هذا المستند ويحدّث الاختبار بما يطابق السلوك المستهدف.

بهذا يبقى التقدم نحو التوحيد بين المسارات قابلًا للقياس والمراجعة.
