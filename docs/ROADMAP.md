# خارطة طريق لسان — تنفيذ مرحلي قابل للقياس

> مرجع معيار الاكتمال: [خط الأساس لاكتمال لسان](COMPLETION-BASELINE.md)

## المرحلة 1) تثبيت خط الأساس

- [x] توحيد تعريف "الاكتمال" للغة والمكتبات والأدوات.
- [x] اعتماد معيار قبول موحد لكل ميزة (اختبارات + توثيق + CI).
- [ ] مواءمة جميع المستندات القديمة مع معيار القبول الجديد.

## المرحلة 2) إكمال نواة اللغة

- [ ] سد الفجوات الدلالية المتبقية (أنواع/وحدات/إغلاقات حسب الحاجة).
- [ ] توحيد السلوك بين المفسّر وVM والمسار الأصلي.
- [x] توثيق الفروقات المعروفة بشكل صريح حتى إغلاقها.

## المرحلة 3) توسيع المكتبة القياسية

- [ ] تثبيت واجهات الملفات/النصوص/JSON/الوقت/البيئة بشكل نهائي.
- [ ] إضافة مكتبات أساسية ناقصة (شبكات، أدوات نظام، اختبار).
- [ ] ضمان أن كل إضافة جديدة مدعومة باختبارات وأمثلة.

## المرحلة 4) تقوية سلسلة الأدوات

- [ ] تحسين CLI وتجربة التشخيص ورسائل الأخطاء.
- [ ] إكمال تجربة المحرر (LSP + VS Code Extension) بشكل متكامل.
- [ ] ربط الأدوات بالتوثيق العملي وأمثلة التشغيل.

## المرحلة 5) الإنتاجية والجاهزية

- [ ] تقديم مدير حزم بسيط مع قفل نسخ (Lockfile) وتدفق نشر مكتبات.
- [ ] تحسين الترجمة الأصلية والأداء واستهلاك الذاكرة.
- [ ] توحيد تجربة التطوير عبر الأنظمة المستهدفة.

## المرحلة 6) الاستقرار والإصدارات

- [ ] رفع تغطية الاختبارات (لغة + تكامل + أمثلة).
- [ ] اعتماد إصدارات مرحلية مع ملاحظات ترقية واضحة.
- [ ] تعريف سياسة استقرار وتوافق بين الإصدارات.

## مبدأ التنفيذ

- كل مرحلة تُنفذ على شكل PRs صغيرة قابلة للمراجعة والاختبار.
- لا تعتمد أي ميزة إلا بعد استيفاء معيار القبول الموحد.
- معيار النجاح هو اكتمال الميزة سلوكيًا، وليس فقط زيادة رقم الإصدار.
